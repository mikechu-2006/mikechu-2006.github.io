博客搭好之后，接下来的事是把旧文章搬过来。这件事比想象中麻烦，麻烦的地方不在复制文本，而在**链接、图片和搜索权重**。

下面是我整理的清单，按顺序做。

## 一、先盘点，再动手

在旧站后台导出文章列表，至少记录这几列：

| 字段 | 用途 |
| --- | --- |
| 旧 URL | 做 301 映射，最重要 |
| 标题 | 核对有没有漏搬 |
| 发布时间 | 保持时间线 |
| 阅读量 / 评论数 | 决定哪些文章值得优先搬 |

导出成 CSV 存好。这份表是后面所有工作的底稿。

## 二、导出正文

不同平台的导出能力差别很大：

- **WordPress**：后台「工具 → 导出」得到 WXR 文件，可用 `wordpress-to-hugo-exporter` 或 `wp2md` 转成 Markdown
- **博客园**：后台有备份功能，能导出 XML
- **CSDN / 掘金 / 简书 / 知乎**：没有官方导出，只能按自己主页的公开页面抓，注意频率，别把账号抓封了
- **微信公众号**：没有导出，只能手工或借助第三方工具

> 抓取自己写的内容是合理的，但请控制请求频率、遵守 robots 协议，不要用登录态做批量操作。

## 三、处理图片

这是最容易翻车的一步。旧站的图片要么有防盗链，要么在平台自己的图床上，换域名之后全部失效。

正确做法：

1. 把所有图片下载到本地 `public/images/` 或对象存储
2. 重命名成有意义的名字（`2023-05-redis-cluster.png` 比 `image-123.png` 好得多）
3. 正文里的图片地址改成相对路径
4. 顺手压缩一遍，能省掉一半流量

## 四、补 front-matter

每篇文章都要有标题、日期、摘要、标签。日期取原始发布时间，不要用迁移时间——否则时间线全乱。

可以写个脚本批量转换，比如：

```python
import re, pathlib

for path in pathlib.Path("posts").glob("*.md"):
    text = path.read_text(encoding="utf-8")
    # 把旧平台的 <!-- more --> 标记去掉
    text = text.replace("<!-- more -->", "")
    path.write_text(text, encoding="utf-8")
```

转换之后一定要**人工过一遍**，重点看：代码块的语言标注、表格、数学公式、内链。

## 五、让旧链接 404 之前先跳转

如果旧站在你自己的域名下，理想情况是给每个旧 URL 配 301。但 GitHub Pages 是纯静态托管，不支持服务端跳转，实际能做的是**给每个旧地址生成一个跳转页**：

```html
<!-- /p/123456/index.html -->
<meta http-equiv="refresh" content="0; url=/blog/redis-cluster/">
<link rel="canonical" href="https://你的域名/blog/redis-cluster/">
<a href="/blog/redis-cluster/">如果没自动跳转，点这里</a>
```

搜索引擎能识别这种跳转，效果远好于 404，只是不如 301 干净。如果旧站文章多、权重高，确实需要真 301，可以把这个仓库同时挂到 Cloudflare Pages（免费），那边支持 `_redirects`，一行一条：

```
/p/123456    /blog/redis-cluster/   301
/archives/9  /blog/                   301
```

把旧域名解析到 Cloudflare Pages 承接跳转，新流量继续走 GitHub Pages，两边内容同源，互不冲突。

如果旧站是别人的平台，你改不了服务器，那就退一步：

- 新文章加 canonical，指回你自己
- 旧文章正文开头加一行「本文已迁移至 <新链接>」
- 旧文章不要删，保住外链和搜索入口

## 六、通知搜索引擎

- Google Search Console 提交新 sitemap；如果换了域名，用「地址更改」工具
- 百度站长平台提交 sitemap
- 检查 GSC 的「网页」报告，看 404 和「已抓取但未编入索引」的页面

## 七、观察四到八周

迁移不是一次性动作。前一个月要盯：

1. 索引数有没有掉
2. 哪些旧链接还在 404（补 301）
3. 外链是否失效
4. 搜索流量有没有恢复

旧站至少保留半年，等新站的排名稳定下来再考虑关停。

## 最后

搬完之后你会发现，真正的收获不是"文章都在一个地方了"，而是**你终于拥有了一份可以随时带走的存档**。这件事本身，比搬多少篇更重要。
