选博客方案的时候，人很容易陷入一种幻觉：只要平台选对了，就会开始写。事实证明，平台只影响你搬家时的痛苦程度。

## 我比较过的四种方案

| 方案 | 上手成本 | 迁移成本 | 可控性 | 适合谁 |
| --- | --- | --- | --- | --- |
| 技术社区（掘金 / CSDN） | 极低 | 高（基本搬不走） | 低 | 只想快速获得流量 |
| WordPress 动态站 | 中 | 中 | 中 | 需要后台和插件生态 |
| 托管博客（Ghost Pro / Substack） | 低 | 中 | 中 | 想写作 + 订阅变现 |
| **静态站（Astro + Pages）** | 中 | **极低** | **高** | 愿意用 Git 的技术作者 |

前三行都有同一个问题：内容和"渲染内容的那套系统"绑在一起。第四行的关键区别是，内容就是文件本身。

## 静态站到底省了什么

一个纯静态站没有服务器进程、没有数据库、没有登录后台。构建时把 Markdown 编译成 HTML，之后所有请求都由 CDN 直接返回文件。

好处很直接：

- **快**：没有数据库查询，首字节通常在几十毫秒
- **稳**：没有运行时，就没有"半夜挂了"这回事
- **便宜**：GitHub Pages 对公开仓库免费，个人博客完全够用
- **安全**：没有后台，就没有后台漏洞

代价是构建时要跑一遍 Node，以及评论、搜索这类动态能力得另外接。

## 为什么是 Astro

我试过 Hugo 和 Hexo，最后选了 Astro，理由有三个：

1. **默认输出零 JavaScript**。页面是纯 HTML + CSS，只有需要交互的组件（比如复制按钮）才加载脚本。
2. **Markdown 是一等公民**。内置 Shiki 语法高亮、GFM、目录提取，不用装一堆插件。
3. **需要时可以加复杂度**。哪天想加个 React 组件做交互，直接加，不用换框架。

它的内容集合还有一层类型校验，front-matter 少写一个字段，构建就会失败：

```ts
const blog = defineCollection({
  loader: glob({ pattern: '**/*.md', base: './src/content/blog' }),
  schema: z.object({
    title: z.string(),
    date: z.coerce.date(),
    tags: z.array(z.string()).default([]),
  }),
});
```

这一点比想象中重要。写了几十篇之后，你一定会忘记某篇的 front-matter 格式，而报错信息会直接告诉你哪一行错了。

## 为什么是 GitHub Pages

- 对公开仓库完全免费，没有服务器费用，也没有续费陷阱
- 跟代码放一起：push 就部署，不用另开一个平台账号
- 自带 HTTPS，地址是 `https://<用户名>.github.io`，可以长期用
- 学生党零成本起步，以后想绑自己的域名随时加

它的边界也要清楚：GitHub Pages 只是静态文件托管，不支持服务端逻辑；在国内访问偶尔会慢。如果你同时想要一个更快的备用入口，同一个仓库再挂一份 Cloudflare Pages（`*.pages.dev`）就行，两边都免费。

对纯文字博客，这些足够了。真的遇到速度问题，再把产物同步到国内对象存储 + CDN，那时候才需要考虑备案。

## 一句话总结

**写作系统应该足够无聊**：没有新功能要学，没有插件要升级，你唯一要做的就是打开编辑器，写。
