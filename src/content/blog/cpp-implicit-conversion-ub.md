## 前言

一般来说最好保证代码中所有运算不包含隐式转换，但是实际许多情况下并不会出现问题，感觉毕竟两个整数，能出什么问题？然后写代码的时候偷懒，所以就不会留意。这里整理一下整数之间可能出现的问题。

所有代码输出测试环境为c++17，GCC 编译器版本14.2.0，win11

## 不涉及无符号整数

### 运算

当int与long long混合运算时，int会隐式提升为long long，并且int的值总能安全转换为long long，因此只要保证不会爆long long就没事。但是要注意一个实现：

```cpp
    int a = 1e9;
	int b = 1e9;
	long long c = a*b*1ll;
	cout << c << endl;
```

输出-1486618624，说明存在越界。这是因为运算顺序是从左到右，int与int间运算，结果类型仍是 int，1e18 超出范围。解决方法：在左侧添加1ll\*

```cpp
	int a = 1e9;
	int b = 1e9;
	long long c = 1ll*a*b;
	cout << c << endl;
```

输出1000000000000000000。

### 格式输入输出

用%d输出或读取long long类型，输出时，%d期望一个int类型参数，但传入long long。long long将被隐式转换成int，如果越界输出错误值，否则没事。

```cpp
	int a = 1e9;
	int b = 1e9;
	long long c = 1ll*a*b;
	printf("d,c=%d\n",c);
	printf("lld,c=%lld\n",c);
	printf("d,a=%d\n",a);
	printf("lld,a=%lld\n",a);
```

输出

```
d,c=-1486618624
lld,c=1000000000000000000
d,a=1000000000
lld,a=1000000000
```

输入时：%d只会填充long long的低32位，高32位保留读入之前的值，对未初始化局部变量导致UB。

```cpp
	long long nm = 0x123456789ABCDEF0;
	scanf("%d",&nm);
	printf("nm=%lld\n",nm);
```

输出nm=1311768464867721224
用%lld输出或读取int类型，输出时：%lld期望一个long long类型参数，但传入int。int的值并非被隐式转换为long long，而是被直接读64位，导致如果int是负数则会输出错误结果（在x86-64下）。
输入时：%lld会覆盖大小为8字节的内存，超过int大小，导致UB。
总结：（在不越界情况下）printf正整数随便用。**scanf不可以混用！**~至少看在取地址符&的面子上，别乱用。~
浮点数不要乱用格式符。记住64位LF 32位lf 16位f就行。

## 无符号整数

除了unsigned int, unsigned long long等明确unsigned的无符号整数，还有.size() .length()返回值是 size\_t，也是无符号整数。char是有符号还是无符号，视编译器而定（GCC/x86 上是有符号的，`char c = 200` 实际存成 -56）。另外，填入数组下标的数最后会被转成size\_t，负数下标会变成天文数字，直接越界。

### 比较操作

有符号和无符号一起比较时，**有符号的那个会转成无符号**（无符号类型不比它窄时）。所以负数会变成很大的正数，结果和预期相反：

```cpp
	long long A = -1;
	size_t B = 2;
	bool f = A < B;
	cout << f << endl;   // 输出 0，A 被转成了 18446744073709551615
```

这也意味着 `v.size() == -1` 永远是 false——`-1` 会先变成 `size_t` 的最大值。想判断"没找到"，要么用 `npos`，要么先把 `size()` 转成有符号。

### 算术运算

和无符号一起做运算，**结果同样是无符号的**：有符号操作数先转成无符号再算。负数一参与就变成巨大正数，不报错也不警告：

```cpp
	size_t a = 0;
	cout << a - 1 << endl;         // 18446744073709551615

	vector<int> v;                 // 空
	cout << v.size() - 1 << endl;  // 18446744073709551615，不是 -1
```

### 一个可以放心的地方

无符号整数的溢出是**定义良好**的，按 2^N 取模回绕：

```cpp
	unsigned int u = 4294967295u;
	cout << u + 1 << endl;   // 0
```

所以哈希、模运算这类"就是要它乱绕"的场合，用 unsigned 不会出事；有符号那边溢出则没有这个保证。

### 输出

`unsigned int` 用 `%u`，`size_t` 用 `%zu`（Windows 上写 `%llu` 也能过，但 `%zu` 跨平台）。混用和上面 `%lld` 的问题一样，读出来的值是错的。

## 总结

c++整数，scanf不能混用，有符号整数与无符号整数比较运算有问题。
